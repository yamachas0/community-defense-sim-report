相談は待ち行列になった

所有者は毎月ほぼ全員が相談する。仲介2人の回答枠は月12件あるのに、実際の回答は月0〜7件に偏り、 未回答が積み上がる（runAでは12か月で115件が未回答のまま終わった）。 回答が届いた所有者でも、その後の月は依然 hold が支配的で、売却に至ったのは runA の2件だけである。

この非対称は世界の設計ではなく、仲介という主体の振る舞いから出ている——ただし次の注意書きが付く。

配線の弱点（この便で発見）：仲介の月次の応答が出力の上限で切れて解析に失敗し、 仲介の月がまるごと消えた（runA 8 / runB 7 / runC 9・いずれも24主体×月のうち）。 相談の一覧（本文つき）が観測に加わって、仲介の内心と回答が長くなったためである。 つまり「仲介が答えない」と「仲介の答えが記録されない」が混ざっている。 この3本の回答率の低さは、その分だけ割り引いて読む必要がある。

行政に面積の分布を見せたら、条例が初めて効いた

v4.1 では行政が置いた閾値は 1件1000㎡超で、A市の区画は最大450㎡だったので、条例は一度も発動しなかった。 行政の観測に区画1件あたりの面積の分布（＝閾値を決める材料）が無かったからである。

  • v4.1b の runA では、行政が第1月から閾値100㎡を選んだ。 その結果、本プロジェクトで初めて届出が実際に発動した（第12月・1件。成立予定は第13月＝12か月の外）。
  • runA の成約1件（第7月）は、この条例の施行後に起きた取得である。
  • runC の行政は 1000㎡ → 500㎡ と下げたが、最大区画450㎡には届かず空振りのまま。 分布を見せても空振りを選ぶ行政はいる。

この結果の限界（先に書く）

  • 2つの変更を同時に入れている。行政は観測を受けて公表と条例を出し、それは全主体へ配送される。 したがって取得や認知の変化を「相談経路のおかげ／せい」と言い切ることはできない。
  • v4.1 にも私信による相談は最初からあった（所有者→仲介 63 / 90 / 31通）。 v4.1b は「経路の復活」ではなく、専用のIDと状態と機械記録と月次の実務量を持つ相談プロトコルの追加である。
  • 仲介の月の3分の1が出力の打切りで失われている（上記）。

この便で直したこと（実走前・外部レビュー）

実走の前に外部レビュー（OpenAI Codex / gpt-5.6-sol）を通し、判定「不可」で返ってきた指摘を潰してから走らせた。

  • 回答済みという状態が同じ月のうちに相談者へ漏れていた。本文が届くのは翌月なので、状態も翌月からにした。 相談が届く前に答えることも不成立にした。
  • IDが二重表記だった（機械記録は [Q0001]、配送は CONSULT-Q0001）。同じ形に統一し、どちらで指されても解決するようにした。
  • 月1件・月6件という有限資源を、入力の形ではなく世界の側で数えるようにした。
  • 遅延0か月の条例で「届出の対象」が偽の0になっていたので、 「対象面積に該当した取得」と「届出で待機した取得」を分けて出すようにした。
  • レポートHTMLが金額のある世界を再導入していた。共通のレポート雛形は金額のある世界のために書かれていて、 「平均賃料」「初期評価額」「◯万」が残り、価格を持たない行に undefined万 とすら出ていた。 この版は金額の欄と文言を外した専用の雛形で描き、出力HTML全文に金額の語が無いことをテストで固定した。

回帰テストは 469本（123本追加）。v4.1 の挙動が1文字も変わっていないことも実測で固定してある （同じmockを再走して帳簿がバイト単位で一致・プロンプト357本が完全一致）。

読み

  • 「相談したい」は口実ではなかった。経路を与えると所有者はほぼ全員が毎月使う。 だが相談できても手放さない。残る候補は「手放しても何も返ってこない」＝対価の不在である。
  • 気づきは相談で加速する。取得を話題にする住民は 20/17/18人、 自分に打診が来ていない月の気づきは 99/55/18件（v4.1 は 44/43/46）。相談と回答は噂の運び手にもなった。
  • 行政に材料を渡すと規制は現実になる。面積の分布を見せただけで、閾値は1000㎡から100㎡へ動き、 届出が初めて実際に掛かった。「規制が効かない」のは規制の意思ではなく、観測の不足だった可能性がある。
